# Athanor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A run-based alchemy puzzle game in Unity (WebGL) with a candlelit pixel-art workshop, a 3x3 bench, hidden recipes, catalysts and reaction cutscenes.

**Architecture:** Game rules are plain C# with no Unity references (`Athanor.Core`), tested both by `dotnet test` and Unity edit-mode. A thin Unity layer (`Athanor.Game`) renders one scene driven by a small state machine. Art is generated by a Node tool from the approved mockup's painter; effects are pixelfx sprite sheets played by a flipbook component.

**Tech Stack:** Unity 6000.6.7f1 (Universal 2D, URP 2D lights, bloom, Pixel Perfect Camera), C#, NUnit, Node 18+ (art and effect export), pixelfx (MIT).

**Spec:** `docs/superpowers/specs/2026-11-11-athanor-design.md` (read it first; the mockup in `docs/mockup/mockup.html` is the visual reference).

## Global Constraints

- Unity editor 6000.6.7f1, Universal 2D template, target WebGL.
- Base resolution 640x360, integer scaling, point filtering on every sprite and font.
- Fonts: Alagard 16/32/48 px headings and numbers; BitPotion 16 px reading text; Pixel Operator tiny labels and card names. Credit line for Alagard. BitPotion licence must be verified, else Pixel Operator.
- No OnGUI. No hand-edits to `Packages/manifest.json`. Packages via the unity-package-management skill.
- No audio, monetization, accounts or localization.
- No names, art or layouts from Balatro, 9 Kings or existing alchemy games.
- `Athanor.Core` must not reference `UnityEngine`.
- Commit only when the user has said to; otherwise leave changes staged-ready and say so.
- `pixel-effects/` (the user's clone) is never modified and is git-ignored.

## Review Focus

1. Ignite with no adjacent pair on the bench: the button is disabled and no trial is spent.
2. Satchel and discard together hold fewer than 5 cards: the hand is smaller, nothing throws.
3. Saved journal in PlayerPrefs is corrupt or from an older shape: the game starts with an empty journal.
4. Clicking rapidly during a cutscene or double-clicking Ignite: one Ignite resolves once; skips never drop score.
5. The same recipe fires twice in one Ignite: only the first counts as a discovery.
6. Browser window not 16:9 or very small: letterboxed, still integer-scaled, UI not clipped.

### Task 4: Bench and Ignite resolution

**Files:** Create `Core/Ignite.cs`, `Tests/EditMode/IgniteTests.cs`.

**Interfaces (Produces):**
```csharp
public sealed class Bench { public readonly string[] Tiles = new string[9]; public int Count { get; } public void Clear(); }
public sealed class ReactionEvent {
  public int TileA, TileB; public string A, B;
  public string Result;        // null => fizzle
  public bool Discovery;       // first time in the journal
  public bool FirstThisRun;
  public long Potency;         // after all multipliers
  public HintData Hint;        // set on fizzle when a new hint exists
}
public static class IgniteResolver {
  public static List<(int a, int b)> Pairs(Bench b, bool diagonals);   // reading order, a < b
  public static bool HasAnyPair(Bench b, bool diagonals);
  public static List<ReactionEvent> Resolve(Bench bench, ContentDb db, Journal journal,
      ISet<string> firedThisRun, IReadOnlyList<CatalystData> catalysts);
}
```
Rules to encode: orthogonal pairs ordered by `a` then `b`; with `Diagonals` add the two diagonal directions. Reaction potency = `BasePotency(resultTier)` x 2 if `FirstThisRun` x n where n is the 1-based index among successful reactions in this Ignite (`ChainPlus`: n+1) x catalyst multipliers (`KindDouble` if either input is that kind: x2; `FirstTriple` on n = 1: x3; `DiscoveryTriple` when `Discovery`: x3) + `EmptyTileBonus.amount` x empty tiles. `CentreTwice`: reactions touching tile 4 are emitted twice; the repeat is never a discovery. Fizzle: potency 0, hint = first partner kind of `A` (then `B`) not already hinted, where a partner exists that is not yet known. Resolve mutates `journal` and `firedThisRun`.

### Task 5: Run state

**Files:** Create `Core/RunState.cs`, `Tests/EditMode/RunStateTests.cs`.

**Interfaces (Produces):**
```csharp
public enum RunPhase { Playing, DepthCleared, ChoosingCatalyst, Lost, Won }
public sealed class IgniteOutcome { public List<ReactionEvent> Events; public long Gained; public RunPhase PhaseAfter; }
public sealed class RunState {
  public RunState(ContentDb db, Journal journal, int seed);
  public int Depth { get; } public long Potency { get; } public int Target { get; }
  public int TrialsLeft { get; } public int RedrawsLeft { get; } public int HandSize { get; }
  public RunPhase Phase { get; }
  public IReadOnlyList<string> Hand { get; } public Bench Bench { get; }
  public IReadOnlyList<CatalystData> Catalysts { get; }
  public bool Place(int handIndex, int tile);   // false if tile occupied or phase != Playing
  public bool Unplace(int tile);                // back to hand
  public bool CanIgnite { get; }                // Playing && HasAnyPair
  public IgniteOutcome Ignite();                // throws InvalidOperationException if !CanIgnite
  public bool Redraw();
  public IReadOnlyList<CatalystData> CatalystOffer { get; } // 3 not yet owned, set on DepthCleared
  public void BeginCatalystChoice();            // DepthCleared -> ChoosingCatalyst
  public void ChooseCatalyst(string id);        // -> Playing at Depth + 1
}
```
Rules: start depth 1, 4 trials (+1 with `ExtraTrial`), 2 redraws (+1 `ExtraRedraw`), hand 5 (+1 `ExtraHand`); satchel = 2 of each starter. Ignite: resolve, add results to satchel (`AddResult`), discard placed and remaining hand, clear bench, add potency, spend a trial; if depth 5 and any event's result is the ultimate => `Won`; else if depth < 5 and potency >= target => `DepthCleared`; else if trials are 0 => `Lost`; else draw a new hand. Potency resets to 0 each depth. At depth 5 trials are 6 and there is no target.
