5b-02 · Dust and ember loops: before / after

The cutscene streams shipped as loops on 2026-11-13 (Phase 4). This page sets them beside the random emitters they replaced so the owner can choose keep or revert. Both sides are ports of the C# (same rates, lives, ranges, colours, rounding), drawn the same way (SparkMesh: centre rounded with Mathf.Round, 1 px dot or 5x5 sparkle, additive), so the only difference on screen is emitter versus loop. Fixed-step simulation, seeded; bloom is an approximation of the URP volume (threshold 1.0, intensity 1.1). Trails (Sparks.Trail) are already approved and not shown.

Dust (the moonbeam over the bench, Bench/Dust.cs) gets no panel: the maths did not change, and the old Px.Snap and the new SparkMesh.Put are the same Mathf.Round of the same local position, the same 1 px dot, the same blend (Glow and ParticleGlow) at order 8. Model notes. Before: Sparks.Update is assumed to step the pool before the cutscene's Update emits, so a new particle is drawn where it was born (the other script order draws it one step on; not visible). The old SpriteRenderer pool also showed a reused sprite for one frame at its previous position; that was a renderer bug fixed with SparkMesh, not part of this choice, and is not drawn. Time.time is float32 as in Unity. Colours are added in display space; the game adds in linear space before bloom and the vignette, so absolute brightness here is approximate, the same on both sides.
